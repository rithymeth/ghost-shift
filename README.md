# Ghost Shift

A 1–4 player online co-op comedy-horror cleaning game for Windows, built on the
[Aether engine](https://github.com/rithymeth/game-ngine). Players run an underqualified paranormal cleaning company in the haunted
city of Grimborough. The design is in the game design document; this repository is the implementation.

**Status: a first-playable vertical slice, all of it placeholder art and placeholder numbers.** One room (a Willow House blockout),
one ghost, twelve pieces of contamination. It has been run and tested on **Linux with a software renderer only**. Nobody has played it,
it has never run on Windows, and it has never been on a real network. Read [`docs/FIRST_PLAYABLE_STATUS.md`](docs/FIRST_PLAYABLE_STATUS.md)
for what is proven and what is not, and [`docs/M0_RESULTS.md`](docs/M0_RESULTS.md) for the evidence, including the bugs found on the way.

## What is in it

| Part | Where | What it is |
|---|---|---|
| Game rules (C++, server-authoritative) | `src/gs/` | cleaning with three tools and per-tool resources, the van, haunting stages and ghost AI, trap and stun, the Caretaker, contract grading and pay, the company save |
| Game server | `server/` | `ghostshift_server`: loads the cooked scene headless and runs every rule (a modified copy of the engine's `aether_server`) |
| First-person client | `client/` | `ghostshift_client`: renders the scene, predicted movement, mouse look, sends input as RPCs, HUD from replicated state |
| Scene, HUD, models | `Content/`, `tools/` | generated by `tools/build_lookdev*.py` and `tools/build_hud.py`; **blockouts, not final art** |
| Tests | `tests/` | 11 test programs plus scripted checks in `tools/` |
| Offline Luau scripts | `Content/Scripts/` | the single-player version of the early rules (cleaning, ghost patrol, HUD). It has **not** been kept in step with the C++ rules (no tank, tools, trap) |

## Controls (client)

WASD move · mouse look · hold left mouse to clean · 1 / 2 / 3 vacuum / UV scrubber / sprayer · F empty the tank and recharge at the van ·
T place a trap · Q stun the ghost · R activate the trap · X extract.
A ghost has to be woken (the haunting rises while you are inside) before it can be stunned; then it has to be inside the trap's radius.

## Build (Linux — this is what has been tested)

You need the Aether engine built and installed as an SDK. The Vulkan and window backends are needed for the client (`libvulkan-dev`,
`glslang-dev`, the X11 development packages), software Vulkan (`mesa-vulkan-drivers`) and `xvfb` if there is no GPU.

```
# in the engine repository
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DAETHER_BUILD_MCP=OFF
cmake --build build
cmake --install build --prefix /path/to/aether-sdk

# in this repository
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_PREFIX_PATH=/path/to/aether-sdk -DGHOSTSHIFT_BUILD_CLIENT=ON
cmake --build build
for t in build/ghostshift_*_test; do $t | tail -1; done      # 11 programs, each prints PASSED
```

Scripted end-to-end checks (each takes a minute or more on a software renderer):

```
tools/assembled_check.sh <this build dir> <engine build dir>                # server + scripted player: retreat, completion (S, 1500), save across restarts
tools/client_check.sh    <this build dir> <this build dir> <engine build dir> # the first-person client: cleans, trap/stun/activate/extract
tools/render_lookdev.sh  <engine build dir>                                 # a screenshot of the scene
```

Run it by hand:

```
<engine build>/tools/cook/aether_cook GHOST-SHIFT.aproject --out cooked --config shipping
GHOSTSHIFT_SAVE_DIR=./company build/ghostshift_server --pak cooked --port 7777
build/ghostshift_client --pak cooked --server 127.0.0.1:7777 --name Maya
```

`GHOSTSHIFT_HAUNTING_RISE=<per second>` speeds up or slows the haunting on the server (a tuning and test override).

## Build (Windows — NOT TESTED; please try it and report what breaks)

The engine's own instructions are the starting point (Visual Studio 2022, x64, D3D12). The same steps, with a few things I would expect to
trip over:

```
# engine repository
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config RelWithDebInfo
cmake --install build --config RelWithDebInfo --prefix C:/aether-sdk

# this repository
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=C:/aether-sdk -DGHOSTSHIFT_BUILD_CLIENT=ON ^
      -DGHOSTSHIFT_DXCOMPILER_DLL=<engine build>/RelWithDebInfo/dxcompiler.dll
cmake --build build --config RelWithDebInfo
```

Things most likely to go wrong, in my order of suspicion: (1) `dxcompiler.dll` missing at start-up (the option above copies it); (2) the
engine's `cmake --install` may stop on a target that was not built (it did on Linux until everything was built); (3) code written and
compiled only against Linux headers (the client's window/graphics section follows the engine's player, which has a Windows branch I could
not compile); (4) the scripted checks are bash scripts and assume Linux tools. The client has never been run on D3D12, so the first
real look at the game's rendering, lighting and shadows (sun shadows are D3D12-only in the engine) is still to come.

## Vendored engine code

`server/` carries modified copies of the engine's dedicated server (`tools/server`): the SDK install does not ship that library.
The changes: pawns carry the Ghost Shift components, predicted movement with a server-side time budget (the engine's movement server trusts
a client's claimed step; a client claiming 0.1 s per tick moved 2.8x too fast), spawn points, and the systems in `server/main.cpp`.
Resync with the engine on an upgrade. The engine's `LICENSE` status was not checked; the font in `Content/fonts` is Roboto (Apache-2.0),
see `THIRD_PARTY_NOTICES.md`.

## Art

Everything visible is a procedural blockout made by `tools/build_lookdev.py`. Production models and textures are the last step and have not
started: no generated assets exist and no credits have been spent.
